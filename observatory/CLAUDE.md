# CLAUDE.md — «Обсерватория траектории» (рабочее название)

Инструмент персональной психометрии по мотивам эссе «Геометрия интеллекта». Обрабатывает данные одной и той же анкеты, которую **один человек** заполняет **раз в год**, и выдаёт отчёт о собственной траектории: что стабильно, что дрейфует, где переломы, насколько «я нынешний» далёк от «я прошлого».

Это **не** тест на интеллект, **не** диагностика и **не** сравнение с другими людьми.

«Ответ» версии 1 — годовой отчёт из шести разделов (см. «Слой 3»), собранный из посчитанных фактов и изложенный LLM-рассказчиком.

---

## Незыблемые принципы (действуют в каждом модуле, нарушать нельзя)

1. **Никогда не выводить один итоговый балл.** Только профиль по осям + полоса неопределённости (анти-IQ-принцип).
2. **Каждая оценка — с интервалом.** Мало данных → широкая полоса, показанная явно, а не спрятанная.
3. **Экстраполяция всегда помечена.** Прогнозы — только с флагом «за пределами наблюдённого» и расширяющейся воронкой.
4. **Каждый вывод несёт метку:** `измерено` / `оценено` / `экстраполировано`.
5. **Сравнение только с самим собой.** Без популяционных норм — никаких «выше/ниже среднего». Статистика точки, а не облака.
6. **Недостаточно данных → честное признание** («нужно ≥N лет»), а не выдуманное число.
7. **Рассказчик не порождает числа.** Все числа — из facts.json; LLM подбирает только слова.
8. **Приватность:** сырые данные, промежуточные сборки и отчёты не попадают в git и не покидают машину.

## Архитектура

```
schemas/*.json + data/answers/*.json
        │
        ▼
[Слой 1 · Scala]  компилятор анкеты: валидация, версии, нормализация
        │  → build/canonical.json
        ▼
[Слой 2 · Python] численное ядро: все вычисления
        │  → build/facts.json
        ▼
[Слой 3 · LLM]    рассказчик: факты → человекочитаемый отчёт
        │  → reports/<year>-report.md
```

Граница между Scala и Python — **только файлы (JSON)**. Никакого FFI, никаких вызовов между рантаймами.

Фронт сбора данных в v1 — CLI и файлы. Телеграм-бот (Python/aiogram, на VPS) — отдельный этап **после** v1.

## Слой 1: компилятор анкеты (Scala)

Назначение: сделать нелегальные состояния непредставимыми и собрать **все** ошибки данных за один проход.

- **Scala 3**, запуск через **scala-cli** (не sbt). Зависимости — минимум: `com.lihaoyi::ujson` для JSON. Тесты: munit.
- Ядро типов:
  ```scala
  sealed trait Scale
  case object Likert5 extends Scale
  case object Binary extends Scale
  case class Numeric(min: Double, max: Double) extends Scale

  case class Question(
    id: String,                    // стабильный id, живёт дольше формулировки
    text: String,
    scale: Scale,
    reversed: Boolean = false,
    context: Option[String] = None // задел под if-then (Tier 3)
  )

  case class SchemaVersion(year: Int, questions: Vector[Question])

  def validate(raw: RawAnswers, schema: SchemaVersion):
    Either[List[DataError], CanonicalResponse]
  ```
- `id` вопроса стабилен между годами. Смена формулировки = запись в `schemas/mappings.json` (`old_id → new_id`, `equivalence: exact | approximate`). Молча менять текст вопроса запрещено.
- Валидация **накапливает** ошибки (значение вне шкалы, неизвестный id, дубликат, незадокументированный пропуск) — `Either[List[DataError], _]`, никаких падений на первой.
- Нормализация: все шкалы → `[0,1]`; `reversed` применяется здесь и только здесь; исходное значение сохраняется рядом с нормализованным.
- Ретроспективные ответы (заполнено сегодня о прошлых годах, по памяти) допустимы только с флагом `retro: true` — ядро обязано учитывать их с пониженным доверием и помечать в отчёте.
- Чего Scala-слой **не делает**: никакой статистики, трендов, агрегатов. Только схема → валидация → нормализация → `canonical.json`.

## Форматы данных (заморожены)

- `schemas/<year>.json` — определение анкеты этого года (поля Question, как выше).
- `schemas/mappings.json` — соответствия id между версиями анкеты.
- `data/answers/<year>.json` — сырые ответы: `{question_id: value}` + мета `{retro: bool, filled_at: date}`.
- `build/canonical.json` — выход компилятора:
  ```json
  {
    "person_id": "...",
    "generated_at": "...",
    "years": [2026, 2027],
    "observations": [
      {"year": 2026, "question_id": "q_x", "value_raw": 4,
       "value": 0.75, "reversed_applied": false,
       "context": null, "retro": false}
    ]
  }
  ```
- `build/facts.json` — выход ядра: только числа и структурированные утверждения с метками (принцип 4) и записями `insufficient_data`. Прозы в facts.json нет.
- `reports/<year>-report.md` — выход рассказчика.
- В `.gitignore` обязательно: `data/`, `build/`, `reports/`.

## Слой 2: численное ядро (Python)

**Python 3.12.** Зависимости: pandas, numpy, statsmodels, ruptures, pytest. Модули маленькие и читаемые, без «умных» обёрток.

Каждый модуль пишет свой блок в facts.json:

1. `core/stability.py` — **паспорт стабильности**: по каждой оси дисперсия вокруг линейного тренда → классификация черта/состояние (пороги в config). Guard: ≥4 лет.
2. `core/drift.py` — **вектор дрейфа**: наклон тренда по каждой оси, топ-3 изменений за период. Guard: ≥3 лет.
3. `core/changepoints.py` — **переломы**: ruptures (PELT, `model="rbf"`, `min_size=2`) по осям/агрегатам. Guard: ≥5 лет.
4. `core/selfdistance.py` — **матрица T×T** расстояний между годовыми профилями (евклид на нормализованных значениях; для каждой пары лет — только общие вопросы). Выход: матрица + «самый далёкий от текущего год».
5. `core/kalman.py` — **уровни с полосами**: statsmodels `UnobservedComponents` (local linear trend) по каждой оси → уровень + 90 % интервал; экстраполяция ровно на 1 год вперёд, только с меткой `экстраполировано`.
6. `core/report_facts.py` — сборка facts.json + отметки достаточности данных по каждому модулю.

Правило малых T: модуль, не добравший лет, пишет `insufficient_data` с требуемым минимумом. Рассказчик обязан озвучить это как есть (принцип 6).

## Слой 3: рассказчик (LLM)

`narrator/narrator.py` — Claude API. Вход: facts.json + шаблон. Выход: `report.md` на русском.

Жёсткие правила:
- Числа — только из facts.json. После генерации — программная проверка: каждое число в отчёте должно существовать в facts.json; иначе отчёт бракуется и перегенерируется.
- Каждый раздел открывается меткой `измерено` / `оценено` / `экстраполировано`.
- Тон спокойный, описательный. Запрещены: диагнозы, советы, коучинг, сравнения с другими людьми.

Разделы отчёта v1:
1. Что стабильно (черты)
2. Что дрейфует и куда
3. Переломы
4. Расстояние до себя прошлого
5. Уровни с полосами + прогноз-воронка на год
6. Ограничения этого отчёта (автоматически из `insufficient_data` и флагов `retro`)

## Синтетические данные — первая задача

Реальных многолетних данных на старте нет (холодный старт), поэтому первым пишется `core/synth.py`: генератор синтетических ответов за N лет с заложенными свойствами — несколько черт (стабильны), несколько состояний (шумят), дрейф по 2–3 осям, ровно один перелом в известном году.

Тесты (pytest): каждый модуль обязан находить на синтетике то, что в неё заложено, — перелом в нужном году, черты как черты, дрейф с верным знаком. Это и есть definition of done для ядра v1.

## Дорожная карта

- **Tier 1 (текущий):** всё описанное выше → затем телеграм-бот сбора (ежегодный опрос, хранение, отправка отчёта).
- **Tier 2:** популяционные нормы и проекции на известные факторные структуры — только при появлении внешних данных; до этого сравнения с другими запрещены принципом 5.
- **Tier 3:** if-then-профили по контекстной колонке (поле `context` уже в схеме); плотные ряды (ежедневные логи) → динамика, Такенс. **Не начинать без явного решения Кима.**

## Чего в проекте НЕ делать

- Не переписывать статистику на Scala: никакого Breeze вместо statsmodels/ruptures.
- Не выносить бота и LLM-слой из Python.
- Не менять формулировки вопросов без записи в mappings.json.
- Не добавлять «общий индекс», «итоговый скор», геймификацию прогресса — противоречит принципу 1.
- Не коммитить data/, build/, reports/.
- Не превращать отчёт в советы, коучинг или диагностику.

## Контекст происхождения

Проект — программная реализация части 3 эссе «Геометрия интеллекта» (человек — не точка, а траектория) и ступени 1 части 5 (сжимающееся тело неопределённости). Годовая частота съёма видит только медленный слой; быстрый слой (состояния) проявляется как межгодовой разброс — это источник данных для паспорта стабильности, а не помеха.
